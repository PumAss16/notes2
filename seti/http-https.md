# Подтема 12: HTTP/HTTPS и TLS

---

## Часть 1. Теория

### 1.1. Что такое HTTP

**HTTP (HyperText Transfer Protocol)** — это протокол прикладного уровня (7-й уровень OSI), который используется для передачи данных в интернете (веб-страниц, картинок, API-запросов). 

**Как работает HTTP:**
Это протокол «Запрос-Ответ». Клиент (браузер или `curl`) отправляет **Запрос** (Request), а сервер (Nginx, Flask) возвращает **Ответ** (Response). Все общение идет в открытом виде (текстом).

**Структура HTTP-запроса:**
*   **Метод (Method):** GET (получить данные), POST (создать), PUT (обновить), DELETE (удалить), PATCH (частично обновить).
*   **Путь (Path):** `/api/users` или `/index.html`.
*   **Заголовки (Headers):** Кто отправляет (`User-Agent`), что ожидает получить (`Accept`), куки (`Cookie`).
*   **Тело (Body):** Данные (например, JSON с логином и паролем при POST).

**Структура HTTP-ответа:**
*   **Код состояния (Status Code):** 200 (ОК), 301 (Редирект), 404 (Не найдено), 500 (Ошибка сервера).
*   **Заголовки:** Тип контента (`Content-Type: application/json`), длина ответа (`Content-Length`).
*   **Тело (Body):** HTML-код страницы или JSON.

**Группы кодов состояния:**
*   **2xx** — Успех (200 OK).
*   **3xx** — Перенаправление (301 Moved Permanently).
*   **4xx** — Ошибка клиента (404 Not Found, 403 Forbidden).
*   **5xx** — Ошибка сервера (500 Internal Server Error, 502 Bad Gateway).

---

### 1.2. Проблема HTTP и появление HTTPS

HTTP передает данные в открытом тексте. Если вы вводите пароль на сайте по HTTP, любой, кто находится в той же сети (например, в кафе с Wi-Fi), с помощью программы-сниффера (`tcpdump`, Wireshark) увидит ваш пароль. 

Чтобы решить эту проблему, придумали **HTTPS (HTTP Secure)**. Это тот же HTTP, но данные зашифрованы с помощью **TLS (Transport Layer Security)**. HTTPS — это не отдельный протокол, это HTTP, упакованный в TLS-шифрование. По умолчанию работает на порту **443** (HTTP — на 80).

---

### 1.3. Что такое TLS и как работает TLS Handshake

**TLS** — это криптографический протокол, который обеспечивает:
1.  **Шифрование:** Никто не может прочитать данные.
2.  **Аутентификацию:** Вы уверены, что общаетесь с настоящим `google.com`, а не с поддельным сайтом.
3.  **Целостность:** Данные не были изменены в пути.

**TLS Handshake** (рукопожатие) — это процесс, при котором клиент и сервер договариваются о ключах шифрования. Это происходит **до** того, как браузер отправит HTTP-запрос.

**Пошаговый TLS Handshake (упрощенно):**
1.  **Client Hello:** Браузер говорит серверу: «Привет, я поддерживаю такие-то алгоритмы шифрования (cipher suites), и вот моя случайная строка (random)».
2.  **Server Hello:** Сервер отвечает: «Привет, я выбираю вот такой алгоритм шифрования, вот моя случайная строка, и вот мой **SSL/TLS-сертификат**».
3.  **Проверка сертификата:** Браузер проверяет сертификат. Он смотрит, подписан ли он доверенным центром сертификации (CA), не истек ли срок действия, и совпадает ли имя домена в сертификате с тем, что в адресной строке.
4.  **Обмен ключами:** Клиент и сервер обмениваются ключами (используя алгоритм Диффи-Хеллмана), чтобы сгенерировать общий секретный ключ (Session Key).
5.  **Шифрование:** С этого момента все данные (включая HTTP-запросы) шифруются общим секретным ключом.

---

### 1.4. Сертификаты

Сертификат — это электронный документ, который подтверждает, что сервер — это действительно `example.com`. Он содержит открытый ключ, имя домена и подпись центра сертификации (CA, например Let's Encrypt, DigiCert).

**Зачем нужен DevOps:**
В реальной работе вы будете постоянно сталкиваться с сертификатами. Nginx, балансировщики (AWS ELB), Kubernetes Ingress — все они требуют настройки SSL-сертификатов. Понимание Handshake нужно для того, чтобы правильно настроить проксирование и не допустить ошибок «Mixed Content» (когда на HTTPS-странице грузятся картинки по HTTP).

---

### 1.5. Reverse Proxy и HTTPS

В продакшене HTTPS обычно терминируется на **reverse proxy** (Nginx или балансировщике), а не на самом приложении (Python/Node.js). 
*   Nginx принимает HTTPS-запрос, расшифровывает его (снимает TLS).
*   Nginx передает обычный HTTP-запрос вашему Python-бэкенду (по localhost).
Это позволяет не нагружать приложение шифрованием и централизованно управлять сертификатами.

## Часть 2. Команды для проверки HTTP/HTTPS в Linux

```bash
curl -I http://example.com          # только заголовки ответа (HTTP)
curl -I https://example.com         # только заголовки ответа (HTTPS)
curl -v https://example.com         # подробный вывод (включая TLS Handshake)
openssl s_client -connect example.com:443   # показать TLS-сертификат
curl -k https://example.com         # игнорировать ошибки сертификата (для теста)
curl -X POST -d '{"key":"value"}' -H "Content-Type: application/json" http://localhost:5000/api/users
```

## Часть 3. 10 вопросов с собеседований

### Вопрос 1. В чем отличие HTTP от HTTPS?

**Ответ:**
HTTP передает данные в открытом виде, уязвим для перехвата. HTTPS — это HTTP, работающий поверх TLS-шифрования. Он обеспечивает шифрование, аутентификацию сервера и целостность данных. HTTP использует порт 80, HTTPS — 443.

### Вопрос 2. Что такое HTTP-методы (GET, POST, PUT, DELETE)?

**Ответ:**
*   **GET** — запрос данных (не меняет состояние сервера).
*   **POST** — создание новой сущности (отправка формы, логин).
*   **PUT** — полное обновление существующей сущности.
*   **DELETE** — удаление сущности.
*   **PATCH** — частичное обновление.

### Вопрос 3. Что означают коды ответов HTTP (2xx, 3xx, 4xx, 5xx)?

**Ответ:**
*   **2xx (200 OK)** — Успешный запрос.
*   **3xx (301 Moved Permanently)** — Перенаправление (редирект).
*   **4xx (404 Not Found, 403 Forbidden)** — Ошибка на стороне клиента (неправильный запрос, нет прав).
*   **5xx (500 Internal Server Error, 502 Bad Gateway)** — Ошибка на стороне сервера (баг в коде, упал бэкенд).

### Вопрос 4. Что такое TLS Handshake?

**Ответ:**
Это процесс установления защищенного соединения. Клиент и сервер договариваются о версии TLS и алгоритмах шифрования, сервер передает свой сертификат для проверки, а затем они генерируют общий сессионный ключ для шифрования дальнейших данных.

### Вопрос 5. Как браузер проверяет сертификат сервера?

**Ответ:**
Браузер проверяет, что сертификат подписан доверенным центром сертификации (CA), срок его действия не истек, и что доменное имя в сертификате совпадает с тем, к которому обращается браузер. Если что-то не так, браузер покажет ошибку (например, `ERR_CERT_AUTHORITY_INVALID`).

### Вопрос 6. Что такое ошибка 502 Bad Gateway и где её искать?

**Ответ:**
502 означает, что веб-сервер (например, Nginx), принимающий запросы от клиента, не смог получить ответ от вышестоящего сервера (например, от Python-бэкенда). В DevOps это часто означает, что приложение упало, не слушает нужный порт или зависло.

### Вопрос 7. Чем отличается 401 (Unauthorized) от 403 (Forbidden)?

**Ответ:**
*   **401 Unauthorized** — клиент не аутентифицирован (не ввел логин/пароль или токен недействителен).
*   **403 Forbidden** — клиент аутентифицирован, но у него нет прав доступа к этому ресурсу.

### Вопрос 8. Что такое статический контент и как Nginx его отдает?

**Ответ:**
Статический контент — это файлы, которые не меняются (HTML, CSS, картинки). Nginx отдает их напрямую с диска очень быстро, без участия Python или баз данных. Для этого в конфиге используется директива `root` и `location`.

### Вопрос 9. Что такое reverse proxy (обратный прокси) в контексте HTTPS?

**Ответ:**
Это сервер (например, Nginx), который стоит перед вашим приложением. Он принимает HTTPS-запросы от клиентов, расшифровывает их (снимает TLS) и передает обычный HTTP-запрос вашему Python-бэкенду. Это позволяет не нагружать Python шифрованием.

### Вопрос 10. Что такое «Mixed Content»?

**Ответ:**
Это ошибка в браузере. Она возникает, когда вы находитесь на защищенной HTTPS-странице, но какой-то ресурс (картинка, скрипт или CSS) загружается по незащищенному HTTP. Браузер блокирует такие элементы для безопасности.
