# Подтема 13: NAT (Network Address Translation) и Firewalls

---

## Часть 1. Теория

### 1.1. Что такое NAT и зачем он нужен

У нас есть **приватные IP-адреса** (`192.168.x.x`, `10.x.x.x`), которые не маршрутизируются в интернете. Дома у вас может быть 10 устройств (телефон, ноутбук, телевизор), и каждому роутер выдает свой приватный IP.

Но как эти устройства выходят в интернет? Провайдер выдает вам **один публичный IP-адрес**. 

**NAT (Network Address Translation)** — это механизм, который подменяет приватные IP-адреса на публичный IP-адрес вашего роутера, когда трафик выходит в интернет, и возвращает ответы обратно.

**Пример работы NAT (SNAT — Source NAT):**
1. Ваш ноутбук (`192.168.1.10:45000`) отправляет запрос на `google.com` (`142.250.74.78:443`).
2. Роутер подменяет ваш IP и порт на свой публичный (`8.8.8.8:56789`) и отправляет запрос в интернет.
3. Google отвечает на `8.8.8.8:56789`.
4. Роутер по своей таблице понимает, что этот ответ для вашего ноутбука, и отправляет его обратно на `192.168.1.10:45000`.

---

### 1.2. Виды NAT

*   **SNAT (Source NAT)** — подмена **исходящего** IP-адреса. Используется, когда устройства локальной сети выходят в интернет через один публичный IP (как в примере выше). В Linux это делается через правило `MASQUERADE` в iptables.
*   **DNAT (Destination NAT)** — подмена **входящего** IP-адреса. Используется для **Port Forwarding** (проброса портов). Например, вы хотите, чтобы по адресу `8.8.8.8:8080` открывался ваш домашний сервер `192.168.1.10:80`. Роутер меняет входящий пакет так, чтобы он попал на внутренний IP.

---

### 1.3. Файрволы (Firewalls)

**Файрвол** — это система, которая контролирует сетевой трафик на основе заданных правил. Он фильтрует пакеты: разрешает (ACCEPT), запрещает (DROP) или отклоняет (REJECT).

В Linux есть несколько уровней работы с файрволами:
1.  **iptables** — низкоуровневый инструмент работы с ядром (Netfilter). Очень мощный, но сложный. Работает с таблицами и цепочками (chains).
2.  **nftables** — современная замена iptables. Более быстрый и удобный синтаксис.
3.  **ufw (Uncomplicated Firewall)** — надстройка над iptables для Ubuntu/Debian. Простой синтаксис для повседневных задач.
4.  **firewalld** — аналог ufw для RHEL/CentOS.

---

### 1.4. Как работают цепочки в iptables/ufw

Файрвол обрабатывает пакеты по **цепочкам** (chains). Основные:
*   **INPUT** — пакеты, идущие **в** ваш сервер (например, кто-то подключается по SSH или открывает сайт).
*   **OUTPUT** — пакеты, исходящие **из** вашего сервера (например, сервер обновляет пакеты или пингует кого-то).
*   **FORWARD** — пакеты, которые проходят **через** сервер (если он работает как роутер).

**Стратегии (политики) файрвола:**
*   **Default Deny (Запрещено всё, что не разрешено)** — самая безопасная. Вы разрешаете только те порты, которые нужны (например, 22, 80, 443).
*   **Default Allow (Разрешено всё, что не запрещено)** — менее безопасная, но проще для тестов.

---

### 1.5. Firewalls в контексте DevOps (Облака и Docker)

*   **Security Groups (AWS, Yandex Cloud):** Это облачные файрволы. Они работают на уровне виртуальной сети (VPC). Вы настраиваете правила: «Разрешить TCP на порт 22 с моего IP» или «Разрешить порт 80 со всего интернета».
*   **Docker:** Docker сам управляет iptables. Когда вы делаете `docker run -p 8080:80`, Docker создает правила DNAT, чтобы пробросить трафик с хоста на контейнер. Если у вас что-то не работает в Docker, первым делом смотрите правила `iptables -t nat -L`.
*   **Kubernetes:** Сетевые политики (Network Policies) работают по тому же принципу — разрешают или запрещают трафик между подами.

---

### 1.6. REJECT vs DROP

*   **DROP** — молча отбрасывает пакет. Клиент будет ждать ответа (таймаут). Это защищает от сканирования портов.
*   **REJECT** — отбрасывает пакет и отправляет клиенту ICMP-сообщение (например, "port unreachable"). Клиент сразу узнает, что соединение отклонено.

## Часть 2. Команды для работы с файрволами (в Linux)

```bash
# ufw (простой)
sudo ufw status verbose          # статус
sudo ufw enable                  # включить
sudo ufw allow 22/tcp            # разрешить SSH
sudo ufw allow 80/tcp            # разрешить HTTP
sudo ufw allow 443/tcp           # разрешить HTTPS
sudo ufw deny 3306               # запретить MySQL
sudo ufw delete allow 80/tcp     # удалить правило

# iptables (низкоуровневый)
sudo iptables -L -n -v           # показать все правила (verbose)
sudo iptables -t nat -L -n -v    # показать правила NAT
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT  # разрешить SSH
```

## Часть 3. 10 вопросов с собеседований

### Вопрос 1. Что такое NAT и зачем он нужен?

**Ответ:**
NAT (Network Address Translation) — механизм подмены IP-адресов. Он позволяет устройствам с приватными IP-адресами выходить в интернет через один публичный IP-адрес роутера, а также используется для проброса портов (Port Forwarding).

### Вопрос 2. В чем разница между SNAT и DNAT?

**Ответ:**
*   **SNAT (Source NAT)** — меняет IP-адрес отправителя (исходящий трафик). Используется, чтобы все устройства в локальной сети выходили в интернет под одним IP.
*   **DNAT (Destination NAT)** — меняет IP-адрес получателя (входящий трафик). Используется для проброса портов, чтобы внешние пользователи могли достучаться до внутреннего сервера.

### Вопрос 3. Что такое файрвол и какие у него есть базовые политики?

**Ответ:**
Файрвол — система фильтрации трафика. Две базовые политики:
*   **Default Deny** — запрещено всё, что не разрешено (безопасно, требует явного разрешения нужных портов).
*   **Default Allow** — разрешено всё, что не запрещено (менее безопасно, но проще).

### Вопрос 4. Какие основные цепочки есть в iptables?

**Ответ:**
*   **INPUT** — входящие пакеты для самого сервера.
*   **OUTPUT** — исходящие пакеты от сервера.
*   **FORWARD** — пакеты, проходящие через сервер (если он работает как роутер или шлюз).

### Вопрос 5. Что такое ufw и чем он отличается от iptables?

**Ответ:**
`ufw` (Uncomplicated Firewall) — это удобная надстройка над `iptables` (в Ubuntu/Debian). `iptables` работает с таблицами и цепочками на низком уровне, а `ufw` позволяет настраивать правила простыми командами (например, `ufw allow 22/tcp`). По сути, `ufw` переводит простые команды в правила `iptables`.

### Вопрос 6. Что такое Port Forwarding?

**Ответ:**
Port Forwarding — это частный случай DNAT, при котором входящий трафик на определенный порт внешнего IP-адреса перенаправляется на определенный порт внутреннего устройства. Например, внешний порт 8080 -> внутренний 192.168.1.10:80.

### Вопрос 7. Где настраиваются файрволы в облаках (AWS, Yandex Cloud)?

**Ответ:**
В облаках используются **Security Groups** (группы безопасности). Это виртуальные файрволы на уровне сети облака. Они настраиваются через консоль облака или API и фильтруют трафик до того, как он попадет на виртуальную машину.

### Вопрос 8. Почему Docker использует iptables и как это влияет на безопасность?

**Ответ:**
Docker использует iptables для маршрутизации трафика между хостом и контейнерами (через DNAT). Безопасность: по умолчанию Docker открывает порты на всех интерфейсах (`0.0.0.0`), что может быть небезопасно. Поэтому при запуске контейнера часто указывают `-p 127.0.0.1:8080:80`, чтобы контейнер был доступен только локально.

### Вопрос 9. Что такое SNAT-маскарадинг (MASQUERADE) в iptables?

**Ответ:**
Это правило для SNAT, которое автоматически подставляет публичный IP-адрес того интерфейса, через который уходит пакет. Используется в роутерах, когда IP-адрес не фиксирован (например, динамический IP от провайдера).

### Вопрос 10. Что такое REJECT и DROP в iptables и в чем разница?

**Ответ:**
*   **DROP** — молча отбрасывает пакет. Клиент будет ждать ответа (таймаут). Это защищает от сканирования портов.
*   **REJECT** — отбрасывает пакет и отправляет клиенту ICMP-сообщение (например, "port unreachable"). Клиент сразу узнает, что соединение отклонено.
