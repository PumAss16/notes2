# Подтема 9: Сети — Модель OSI и базовые протоколы

---

## Часть 1. Теория

### 1.1. Зачем нужна модель OSI

**Модель OSI (Open Systems Interconnection)** — это теоретическая модель, которая разбивает процесс передачи данных по сети на **7 уровней**. 

Зачем это нужно:
*   Чтобы стандартизировать работу сетей (чтобы оборудование Cisco, Linux, Windows и Mac могли общаться между собой).
*   Чтобы упростить диагностику. Если сайт не открывается, вы знаете, на каком уровне искать проблему (кабель? DNS? порт? само приложение?).

*(В реальности интернет работает по модели TCP/IP, где 7 уровней OSI схлопнуты в 4, но OSI используют как эталон для обучения и диагностики).*

---

### 1.2. Семь уровней OSI (сверху вниз)

Запомнить порядок с 7-го по 1-й уровень помогает фраза: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing.

#### Уровень 7: Application (Прикладной)
*   **Что делает:** То, с чем взаимодействует пользователь и программы. Здесь живут веб-сайты, почта, базы данных.
*   **Протоколы:** HTTP/HTTPS, DNS, SSH, FTP, SMTP, DHCP.
*   **В Linux:** `curl`, `wget`, браузер, `ssh`.

#### Уровень 6: Presentation (Представления)
*   **Что делает:** Шифрование, сжатие, кодировка. Отвечает за то, чтобы данные были понятны получателю.
*   **Протоколы/Стандарты:** SSL/TLS (шифрование HTTPS), ASCII/UTF-8 (кодировка), JPEG/PNG, MPEG.

#### Уровень 5: Session (Сеансовый)
*   **Что делает:** Устанавливает, управляет и разрывает сессии (сеансы связи) между приложениями.
*   **Пример:** Куки (cookies) на сайтах. Когда вы логинитесь, создается сессия.

#### Уровень 4: Transport (Транспортный) ⭐
*   **Что делает:** Разбивает данные на куски (сегменты) и отвечает за их доставку. Решает, как передавать: надежно (TCP) или быстро (UDP).
*   **Протоколы:** TCP, UDP.
*   **В Linux:** Команда `ss -tuln` показывает, какие порты слушают TCP/UDP.

#### Уровень 3: Network (Сетевой) ⭐
*   **Что делает:** Маршрутизация. Определяет, по какому пути (через какие роутеры) пакет пойдет от вашего ПК до сервера. Использует IP-адреса.
*   **Протоколы:** IPv4, IPv6, ICMP (пинг), ARP (поиск MAC по IP).
*   **Устройства:** Роутеры (маршрутизаторы).
*   **В Linux:** `ip a` (адреса), `ip route` (маршруты), `ping`.

#### Уровень 2: Data Link (Канальный)
*   **Что делает:** Передача данных внутри локальной сети (между вашим ПК и Wi-Fi роутером). Использует MAC-адреса.
*   **Протоколы:** Ethernet, Wi-Fi (802.11).
*   **Устройства:** Свитчи (коммутаторы).
*   **В Linux:** `ip link` (MAC-адреса), `ip neigh` (ARP-таблица).

#### Уровень 1: Physical (Физический)
*   **Что делает:** Передача битов (0 и 1) по физической среде: медные провода, оптоволокно, радиоволны Wi-Fi.

---

### 1.3. Главные протоколы: TCP vs UDP

#### TCP (Transmission Control Protocol)
*   **Надежный.** Устанавливает соединение (TCP 3-way Handshake).
*   Проверяет доставку (ждет подтверждений ACK).
*   Если пакет потерялся — отправляет заново.
*   **Где используется:** Веб (HTTP/HTTPS), SSH, базы данных (PostgreSQL), почта.
*   **Аналогия:** Заказное письмо с уведомлением о вручении.

#### UDP (User Datagram Protocol)
*   **Быстрый.** Не устанавливает соединение. Просто отправляет пакеты.
*   Не проверяет доставку (потерялся — значит потерялся).
*   **Где используется:** Стриминг видео, онлайн-игры, VoIP (звонки), **DNS** (запросы к DNS-серверам).
*   **Аналогия:** Листовка в почтовом ящике.

---

### 1.4. DNS (Domain Name System)
Это "телефонная книга" интернета. 
Компьютеры общаются по IP-адресам (например, `142.250.74.78`), но люди запоминают домены (`google.com`). 
DNS-сервер переводит домен в IP-адрес. Обычно использует UDP (порт 53).

---

### 1.5. Что происходит, когда вы вводите адрес в браузере (Классика собеседований)

1. **Браузер и кэш (Уровень 7):** Вы вводите `google.com`. Браузер проверяет свой кэш и кэш ОС.
2. **DNS-запрос (Уровень 7/4):** Если в кэше нет, ОС отправляет запрос на DNS-сервер (обычно UDP). Получает IP.
3. **TCP Handshake (Уровень 4):** Браузер инициирует TCP-соединение с сервером (порт 443).
   *   Браузер -> Сервер: `SYN`
   *   Сервер -> Браузер: `SYN-ACK`
   *   Браузер -> Сервер: `ACK`
4. **TLS Handshake (Уровень 6):** Устанавливается HTTPS-шифрование. Обмен ключами.
5. **HTTP-запрос (Уровень 7):** Браузер отправляет `GET / HTTP/1.1`.
6. **Маршрутизация (Уровень 3):** Пакеты с ответом проходят через роутеры обратно к вашему ПК.
7. **Отрисовка:** Браузер получает HTML, запрашивает картинки (CSS/JS) и рисует страницу.

## Часть 2. Команды для просмотра сети в Linux

### 2.1. IP-адреса и маршруты (Уровень 3)
```bash
ip a                        # показать все IP-адреса интерфейсов
ip addr                     # то же самое
ip route                    # показать таблицу маршрутизации (шлюз по умолчанию)
```

### 2.2. Проверка связи (Уровень 3, ICMP)
```bash
ping -c 4 8.8.8.8           # отправить 4 ICMP-пакета на IP (проверка связи)
ping -c 4 google.com        # проверить DNS + связь
```

### 2.3. Открытые порты и сокеты (Уровень 4)
```bash
ss -tuln                    # все открытые TCP(-t) и UDP(-u) порты, в виде номеров(-n)
ss -tulpn                   # с указанием программ (PID/process)
lsof -i :5000               # кто слушает конкретный порт
```

### 2.4. MAC-адреса и ARP (Уровень 2)
```bash
ip link                     # показать MAC-адреса сетевых карт
ip neigh                    # показать ARP-таблицу (IP -> MAC)
```

## Часть 3. 10 вопросов с собеседований

### Вопрос 1. Назовите 7 уровней OSI.
**Ответ:**
Application (7), Presentation (6), Session (5), Transport (4), Network (3), Data Link (2), Physical (1).

### Вопрос 2. На каком уровне работает HTTP? TCP? IP?
**Ответ:**
*   **HTTP** — Application (Уровень 7).
*   **TCP/UDP** — Transport (Уровень 4).
*   **IP/ICMP** — Network (Уровень 3).

### Вопрос 3. В чем отличие TCP от UDP?
**Ответ:**
**TCP** — надежный, устанавливает соединение (handshake), проверяет доставку пакетов, восстанавливает потери. Используется в вебе, SSH, БД.
**UDP** — быстрый, без установки соединения, не проверяет доставку. Используется в DNS, стриминге, онлайн-играх.

### Вопрос 4. Что такое DNS и как он работает?
**Ответ:**
DNS — это система доменных имен, которая переводит понятные человеку адреса (google.com) в IP-адреса компьютеров (142.250.74.78). Работает в основном по протоколу UDP на 53 порту.

### Вопрос 5. Что происходит, когда вы вводите адрес сайта в браузере?
**Ответ:**
1. Проверка кэша браузера и ОС.
2. DNS-запрос для получения IP.
3. TCP 3-way Handshake с сервером (SYN, SYN-ACK, ACK).
4. TLS Handshake (шифрование).
5. Отправка HTTP-запроса GET.
6. Сервер отвечает, браузер отрисовывает страницу.

### Вопрос 6. Что такое TCP 3-way Handshake?
**Ответ:**
Это процесс установки TCP-соединения:
1. Клиент отправляет пакет **SYN** (синхронизация).
2. Сервер отвечает **SYN-ACK** (согласен).
3. Клиент отправляет **ACK** (подтверждение).
Только после этого начинается передача данных.

### Вопрос 7. Что такое ARP?
**Ответ:**
ARP (Address Resolution Protocol) — протокол, который ищет MAC-адрес устройства по его IP-адресу в локальной сети.

### Вопрос 8. Какая команда покажет открытые порты в Linux?
**Ответ:**
`ss -tuln` (или устаревшая `netstat -tuln`). 
`-t` — TCP, `-u` — UDP, `-l` — listening (слушающие), `-n` — показывать номера, а не имена.

### Вопрос 9. Как проверить связь с сайтом на уровне сети?
**Ответ:**
Командой `ping <адрес>`. Она использует протокол ICMP (Network layer). Если пинг есть, а сайт не открывается — проблема на уровне приложения (7) или порта (4).

### Вопрос 10. Где в Linux посмотреть IP-адрес и шлюз по умолчанию?
**Ответ:**
IP-адрес — `ip a` (или `ip addr`).
Шлюз (роутер, через который идет интернет) — `ip route` (строка `default via ...`).
