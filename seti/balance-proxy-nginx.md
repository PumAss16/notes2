# Подтема 14: Балансировка нагрузки и прокси

---

## Часть 1. Теория

### 1.1. Зачем нужна балансировка нагрузки

Представьте, что ваш сайт стал популярным, и один сервер (Flask/Python) уже не справляется с трафиком. Он начинает тормозить, а потом и вовсе падает. 

Решение — запустить **несколько копий** вашего приложения (например, на трех серверах или в трех контейнерах). Но тогда возникает вопрос: как распределить входящие запросы пользователей между этими тремя серверами, чтобы один не был перегружен, а другой не простаивал? 

Эту задачу решает **Балансировщик нагрузки (Load Balancer)**.

---

### 1.2. Что такое прокси (Proxy)

**Прокси** — это посредник. Он стоит между клиентом и сервером и передает данные туда-обратно.

*   **Forward Proxy (Прямой прокси):** Стоит перед клиентом. Например, в офисе все сотрудники ходят в интернет через прокси, который фильтрует запрещенные сайты. Сервер (Google) видит IP прокси, а не сотрудника.
*   **Reverse Proxy (Обратный прокси):** Стоит перед серверами. Клиенты думают, что они общаются с одним сервером, а на самом деле запрос идет на прокси, который решает, какому из внутренних серверов его передать. **Nginx** — самый популярный reverse proxy в мире.

---

### 1.3. L4 и L7 Балансировка (Главное отличие)

Балансировщики могут работать на разных уровнях модели OSI. От этого зависит, **как** они распределяют трафик.

**L4 (Транспортный уровень) Балансировщик:**
*   Работает на **Транспортном уровне (Transport Layer)**.
*   **Не видит содержимое** пакетов. Он смотрит только на IP-адрес и порт.
*   Просто берет TCP-соединение и перенаправляет его на один из серверов.
*   **Плюсы:** Очень быстрый, выдерживает миллионы соединений.
*   **Минусы:** Не может маршрутизировать запросы в зависимости от URL (например, `/api` на один сервер, `/images` на другой).
*   *Примеры:* AWS Network Load Balancer (NLB), HAProxy (в режиме TCP), LVS (Linux Virtual Server).

**L7 (Прикладной уровень) Балансировщик:**
*   Работает на **Прикладном уровне (Application Layer)**.
*   **Видит содержимое** (заголовки, URL, cookies).
*   **Плюсы:** Умная маршрутизация. Может отправлять `/api` на бэкенд, а `/static` на сервер со статикой. Может терминировать SSL (расшифровывать HTTPS).
*   **Минусы:** Чуть медленнее (нужно читать HTTP-заголовки), но для современных серверов это не проблема.
*   *Примеры:* Nginx, HAProxy (HTTP mode), AWS Application Load Balancer (ALB).

---

### 1.4. Алгоритмы балансировки
Как именно балансировщик выбирает сервер?
*   **Round Robin:** По очереди (запрос 1 -> Сервер А, запрос 2 -> Сервер Б, запрос 3 -> Сервер В).
*   **Least Connections:** Отправляет запрос на сервер, у которого меньше всего активных соединений (самый умный для долгих запросов).
*   **IP Hash:** Привязывает клиента к одному серверу на основе его IP (нужно для сессий).

---

### 1.5. Балансировка в Kubernetes (Ingress)

В Kubernetes балансировка встроена в архитектуру:
*   **Service (L4):** Когда вы создаете Service (например, `ClusterIP`), Kubernetes создает виртуальный IP. Трафик на этот IP распределяется между подами через `kube-proxy` (это балансировка на Транспортном уровне).
*   **Ingress (L7):** Это правило маршрутизации на Прикладном уровне. Ingress-контроллер (обычно это Nginx) смотрит на URL и решает: `myapp.com/api` -> Service `backend`, `myapp.com/` -> Service `frontend`.

## Часть 2. Пример конфигурации Nginx как балансировщика

```nginx
# В блоке http (или в отдельном файле)
upstream my_backend {
    server 127.0.0.1:5000;
    server 127.0.0.1:5001;
    server 127.0.0.1:5002;
}

server {
    listen 80;
    
    location / {
        proxy_pass http://my_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## Часть 3. 10 вопросов с собеседований

### Вопрос 1. Что такое Reverse Proxy и чем он отличается от Forward Proxy?

**Ответ:**
*   **Forward Proxy** стоит перед клиентом и скрывает клиента от сервера (используется для обхода блокировок или корпоративной фильтрации).
*   **Reverse Proxy** стоит перед сервером и скрывает серверы от клиента (используется для балансировки, кэширования и SSL-терминации). Клиент думает, что общается с одним сервером.

### Вопрос 2. В чем главное отличие L4 от L7 балансировщика?

**Ответ:**
L4 работает на **Транспортном уровне (Transport Layer)** и не видит содержимое запроса (только IP и порты). Он очень быстрый.
L7 работает на **Прикладном уровне (Application Layer)** и видит URL, заголовки, cookies. Он позволяет делать умную маршрутизацию (например, `/api` на один сервер, а `/images` на другой) и терминировать SSL.

### Вопрос 3. Что такое SSL-терминация (SSL Termination)?

**Ответ:**
Это процесс, при котором балансировщик (например, Nginx) принимает зашифрованный HTTPS-трафик от клиента, расшифровывает его и передает внутренним серверам (бэкенду) обычный HTTP-трафик. Это снимает нагрузку шифрования с приложений.

### Вопрос 4. Какие алгоритмы балансировки нагрузки вы знаете?

**Ответ:**
*   **Round Robin** — по очереди.
*   **Least Connections** — на сервер с наименьшим количеством активных соединений.
*   **IP Hash** — привязка клиента к серверу по IP (для сохранения сессий).

### Вопрос 5. Что такое sticky sessions (сессии с привязкой)?

**Ответ:**
Это когда балансировщик запоминает клиента и всегда отправляет его запросы на один и тот же сервер (например, через cookie). Это нужно для приложений, которые хранят данные о пользователе в памяти (но лучше хранить их в базе или Redis).

### Вопрос 6. Как Nginx используется в качестве балансировщика?

**Ответ:**
В конфиге Nginx создается блок `upstream`, где перечисляются IP-адреса и порты бэкендов. Затем в блоке `location` используется `proxy_pass` на этот `upstream`. Nginx по умолчанию использует алгоритм Round Robin.

### Вопрос 7. Что такое Ingress в Kubernetes?

**Ответ:**
Ingress — это объект Kubernetes, который описывает правила маршрутизации внешнего HTTP/HTTPS-трафика на внутренние сервисы (Services) на основе URL (на Прикладном уровне). Для работы Ingress нужен Ingress Controller (обычно это Nginx).

### Вопрос 8. Как Kubernetes делает балансировку на уровне L4 (Service)?

**Ответ:**
Kubernetes создает виртуальный IP (ClusterIP) для сервиса. Компонент `kube-proxy` на каждом узле настраивает iptables (или IPVS), чтобы перенаправлять трафик на этот IP на один из подов сервиса по алгоритму Round Robin.

### Вопрос 9. Что такое Health Checks в контексте балансировки?

**Ответ:**
Это проверки, которые балансировщик отправляет серверам (например, GET `/health`). Если сервер не отвечает, балансировщик исключает его из пула и перестает отправлять туда трафик, пока сервер не восстановится.

### Вопрос 10. Что такое CDN и как он связан с балансировкой?

**Ответ:**
CDN (Content Delivery Network) — это глобальная сеть серверов, которая кэширует статический контент (картинки, видео, CSS) ближе к пользователю. С точки зрения балансировки, CDN — это огромный гео-балансировщик, который отправляет запрос на ближайший к пользователю сервер.
