# Подтема 6: Диски и файловые системы

---

## Часть 1. Теория

### 1.1. Как устроены диски в Linux

В Linux всё — файл. Диски представляются как **блочные устройства** в `/dev/`.

**Иерархия:**
```
/dev/sda          — весь диск
/dev/sda1         — первый раздел
/dev/sda2         — второй раздел
```

**Типы устройств:**
- **sda, sdb** — SATA/SCSI диски.
- **nvme0n1** — NVMe SSD.
- **vda, vdb** — виртуальные диски (KVM).
- **loop** — loop-устройства (ISO, snap).

---

### 1.2. Разделы и файловые системы

**Раздел (partition)** — логическая часть диска.

**Файловая система (ФС)** — способ организации данных:
- **ext4** — стандарт для Linux.
- **xfs** — для больших файлов и серверов.
- **btrfs** — современная, со снапшотами.
- **tmpfs** — в оперативной памяти.
- **nfs** — сетевая ФС.
- **swap** — для подкачки.

```bash
lsblk                  # структура дисков и разделов
lsblk -f               # с файловыми системами
fdisk -l               # разделы всех дисков
blkid                  # UUID и типы ФС
```

---

### 1.3. Монтирование

**Монтирование** — подключение ФС к директории (точке монтирования).

```bash
mount /dev/sdb1 /mnt/data   # смонтировать
umount /mnt/data            # отмонтировать
```

**Автоматическое монтирование — /etc/fstab:**
```
# <device>    <mount point>  <type>  <options>  <dump> <pass>
UUID=abc123   /              ext4    defaults   0      1
UUID=def456   /home          ext4    defaults   0      2
/dev/sdb1     /mnt/data      xfs     defaults   0      0
```

**Важно:** ошибка в `/etc/fstab` → система не загрузится. Проверять через `mount -a`.

**Фраза для собеса:**
> Монтирование — подключение ФС к директории. Автомонтирование — через `/etc/fstab`. Ошибка в fstab → система не загрузится.

---

### 1.4. inode — что это и зачем

**inode** — структура, хранящая метаданные файла: права, владелец, размер, время, указатели на блоки. **Имя файла хранится в директории**, а не в inode.

**Что важно:**
- Каждый файл имеет уникальную inode в пределах ФС.
- Если inode закончатся — новые файлы не создадутся.
- Много маленьких файлов быстро расходуют inode.

```bash
df -i
# Filesystem      Inodes  IUsed   IFree IUse% Mounted on
# /dev/sda1      6553600 6553600       0  100% /
```

**Фраза для собеса:**
> inode — метаданные файла. Если закончатся inode, новые файлы не создадутся, даже если место есть. Проверять `df -i`.

---

### 1.5. Жёсткие и символические ссылки

| Характеристика | Жёсткая ссылка | Символическая ссылка |
|:---|:---|:---|
| Команда | `ln file hardlink` | `ln -s file symlink` |
| Указывает на | inode | путь к файлу |
| Можно для директорий | Нет | Да |
| Если удалить оригинал | Файл доступен | Ссылка «битая» |
| Занимает место | Нет (та же inode) | Да |
| Работает между ФС | Нет | Да |

```bash
ls -li file hardlink symlink
# 1234567 -rw-r--r-- 2 user user 100 file
# 1234567 -rw-r--r-- 2 user user 100 hardlink
# 1234570 lrwxrwxrwx 1 user user   4 symlink -> file
```

У `file` и `hardlink` одинаковая inode и счётчик ссылок = 2.

**Фраза для собеса:**
> Жёсткая ссылка указывает на inode, символическая — на путь. Жёсткую нельзя для директорий и между ФС.

### 1.6. LVM — Logical Volume Manager

**LVM** — прослойка между дисками и ФС. Позволяет объединять диски, расширять разделы на лету, делать снапшоты.

**Три уровня:**
```
Physical Volume (PV)     — физический диск или раздел
  ↓
Volume Group (VG)        — пул из нескольких PV
  ↓
Logical Volume (LV)      — «раздел» для ФС
```

**Пример:**
```bash
pvcreate /dev/sdb /dev/sdc
vgcreate myvg /dev/sdb /dev/sdc
lvcreate -L 100G -n mylv myvg
mkfs.ext4 /dev/myvg/mylv
mount /dev/myvg/mylv /mnt/data

# Расширить на лету
lvextend -L +50G /dev/myvg/mylv
resize2fs /dev/myvg/mylv
```

**Зачем:**
- Добавить диск и расширить ФС без перезагрузки.
- Снапшоты для бэкапов.
- Гибкое управление местом.

**Фраза для собеса:**
> LVM — прослойка между дисками и ФС. Три уровня: PV → VG → LV. Позволяет расширять разделы на лету.

---

### 1.7. RAID — избыточность дисков

**RAID** — объединение дисков для отказоустойчивости или производительности.

| Уровень | Что делает | Мин. дисков | Отказоустойчивость |
|:---|:---|:---|:---|
| **RAID 0** | Чередование | 2 | Нет |
| **RAID 1** | Зеркало | 2 | Да (1 диск) |
| **RAID 5** | Чередование + чётность | 3 | Да (1 диск) |
| **RAID 6** | Чередование + двойная чётность | 4 | Да (2 диска) |
| **RAID 10** | Зеркало + чередование | 4 | Да (по 1 на пару) |

```bash
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc
cat /proc/mdstat
mdadm --detail /dev/md0
```

**Важно:** RAID — это **не бэкап**. Если удалить файл — он удалится на всех дисках.

**Фраза для собеса:**
> RAID 0 — чередование, RAID 1 — зеркало, RAID 5 — чётность, RAID 10 — зеркало + чередование. RAID — не бэкап.

## Часть 2. Команды с флагами

### 2.1. Просмотр дисков и разделов

```bash
lsblk                     # структура дисков и разделов
lsblk -f                  # с файловыми системами
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
fdisk -l                  # разделы всех дисков
blkid                     # UUID и типы ФС
parted -l                 # альтернатива fdisk
```

---

### 2.2. Монтирование

```bash
mount                     # смонтированные ФС
mount /dev/sdb1 /mnt/data
umount /mnt/data
umount -l /mnt/data       # ленивое отмонтирование
mount -a                  # смонтировать всё из fstab
cat /etc/fstab            # таблица автомонтирования
findmnt                   # дерево монтирований
```

---

### 2.3. Место и inode

```bash
df -h                     # место на дисках
df -i                     # inode
df -hT                    # с типом ФС
du -sh /path              # размер директории
du -sh * | sort -hr | head -10   # топ-10 больших
du -h --max-depth=1 /var  # размер поддиректорий
```

---

### 2.4. Ссылки

```bash
ln file hardlink          # жёсткая ссылка
ln -s file symlink        # символическая ссылка
ls -li file hardlink      # проверить inode
readlink symlink          # куда указывает симлинк
```

---

### 2.5. LVM

```bash
pvcreate /dev/sdb         # создать PV
pvs                       # список PV
vgcreate myvg /dev/sdb    # создать VG
vgs                       # список VG
lvcreate -L 100G -n mylv myvg   # создать LV
lvs                       # список LV
lvextend -L +50G /dev/myvg/mylv # расширить LV
resize2fs /dev/myvg/mylv  # расширить ФС
```

---

### 2.6. RAID

```bash
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc
cat /proc/mdstat
mdadm --detail /dev/md0
mdadm --fail /dev/md0 /dev/sdb
mdadm --remove /dev/md0 /dev/sdb
```

---

### 2.7. Поиск удалённых файлов, держащихся процессом


### Вопрос 2. Что такое "No space left on device", но место на диске есть?

**Ответ:**

**Причина:** закончились **inode**, а не место.

**Как проверить:**
```bash
df -h      # место есть
df -i      # inode = 100%
```

**Как исправить:**
1. Найти директорию с множеством маленьких файлов.
2. Удалить ненужные (логи, кэш, сессии).
3. Настроить ротацию логов.

**Фраза для собеса:**
> "No space left on device", но место есть — закончились inode. Проверить `df -i`.

---

### Вопрос 3. Чем отличается df от du?

**Ответ:**

| Команда | Что показывает |
|:---|:---|
| **df** | Место на дисках |
| **du** | Что занимает место (по директориям) |

**Важно:** если `df` говорит, что диск полон, а `du` не находит больших файлов — возможно, удалённый файл держится процессом.

```bash
lsof | grep deleted
lsof +L1
```

**Фраза для собеса:**
> `df` — место на диске, `du` — что его занимает. Если df полон, а du не находит — удалённый файл держится процессом.

### Вопрос 7. Что такое /etc/fstab и что будет, если там ошибка?

**Ответ:**

**/etc/fstab** — таблица автоматического монтирования ФС при загрузке.

```
# <device>    <mount point>  <type>  <options>  <dump> <pass>
UUID=abc123   /              ext4    defaults   0      1
```

**Если ошибка в fstab:**
- Система **не загрузится** (упадёт в emergency mode).
- Нужно загрузиться в single-user mode и исправить.

**Как проверить перед перезагрузкой:**
```bash
mount -a      # смонтировать всё из fstab
```

**Фраза для собеса:**
> /etc/fstab — таблица автомонтирования. Ошибка в fstab → система не загрузится. Проверять `mount -a`.

### Вопрос 8. Как расширить диск на лету?

**Ответ:**

**Если используется LVM:**
```bash
# Добавить новый диск в VG
vgextend myvg /dev/sdd

# Расширить LV
lvextend -L +50G /dev/myvg/mylv

# Расширить ФС
resize2fs /dev/myvg/mylv     # ext4
xfs_growfs /mnt/data         # xfs
```

**Без LVM** — сложнее: нужно разбить диск, скопировать данные, изменить разделы.

**Фраза для собеса:**
> С LVM: vgextend → lvextend → resize2fs. Без LVM — сложнее.

### Вопрос 9. Как найти файл, который занимает место, но уже удалён?

**Ответ:**

**Причина:** процесс держит файловый дескриптор удалённого файла. Место не освобождается, пока процесс не завершится.

**Как найти:**
```bash
lsof | grep deleted
lsof +L1
```

**Как освободить:**
1. Перезапустить процесс.
2. Или очистить файл через `/proc/<PID>/fd/<FD>`:
   ```bash
   : > /proc/<PID>/fd/<FD>
   ```

**Фраза для собеса:**
> Если df полон, а du не находит — процесс держит удалённый файл. Найти через `lsof | grep deleted`, перезапустить процесс.

### Вопрос 10. Что такое swap и зачем он нужен?

**Ответ:**

**Swap** — область на диске для расширения RAM. Когда RAM заканчивается, ядро выгружает неиспользуемые страницы в swap.

**Когда используется:**
- RAM заканчивается.
- Процессы неактивны.

**Проблема:** swap на диске медленнее RAM в сотни раз. Активное использование = тормоза.

```bash
free -h      # Swap used
vmstat 1 5   # si, so
swapon --show
```

**Фраза для собеса:**
> Swap — расширение RAM на диске. Активное использование swap = тормоза. Смотреть `free -h`, `vmstat`.
