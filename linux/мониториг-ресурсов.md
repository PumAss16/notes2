# Подтема 5: Мониторинг ресурсов

---

## Часть 1. Теория

### 1.1. Зачем нужен мониторинг

DevOps-инженер должен понимать, что происходит с системой: сколько CPU, памяти, диска и сети потребляют процессы.

**Зачем:**
- Диагностика тормозов.
- Поиск утечек памяти.
- Планирование мощностей.
- Предотвращение падений.

---

### 1.2. Главные инструменты

**top** — базовая команда, есть везде. Показывает процессы в реальном времени.
**htop** — улучшенная версия (цветной, интерактивный), но не везде установлена.

**Верхняя часть top:**
- `load average` — средняя нагрузка за 1, 5, 15 минут.
- `us` — время CPU на пользовательские процессы.
- `sy` — время CPU на системные вызовы.
- `wa` — I/O Wait (CPU ждёт диск).
- `id` — простой CPU.
- `si` — системные прерывания.
- `hi` — аппаратные прерывания.

**Нижняя часть top:**
- Таблица процессов: PID, USER, %CPU, %MEM, TIME, COMMAND.
- Сортировка: `P` — по CPU, `M` — по памяти.

---

### 1.3. load average — как читать

**Load average** — среднее количество процессов в состоянии R (running) и D (uninterruptible sleep) за 1, 5 и 15 минут.

**Формула:** `LA = R + D`

**Как интерпретировать:**
- LA = числу ядер — система загружена оптимально.
- LA < числа ядер — есть запас.
- LA > числа ядер — процессы ждут CPU.
- LA растёт, а CPU простаивает — виноваты D-процессы (I/O wait).

```bash
uptime
# load average: 4.50, 2.30, 1.20
```

**Важно:** LA не показывает, из-за чего нагрузка. Смотреть на `us`, `sy`, `wa`.

**Фраза для собеса:**
> Load average — среднее количество R и D процессов. Если LA высокий, а CPU свободен — виноваты D-процессы (I/O wait).

---

### 1.4. us, sy, wa, id — что означают

| Метрика | Что означает | На что указывает |
|:---|:---|:---|
| **us** | User — время CPU на пользовательские процессы | Высокий us — приложение грузит CPU |
| **sy** | System — время CPU на системные вызовы | Высокий sy — много syscall |
| **wa** | I/O Wait — CPU ждёт диск | Высокий wa — проблема с диском/NFS |
| **id** | Idle — простой CPU | Высокий id — система не загружена |
| **si** | Software Interrupts | Высокий si — много прерываний |
| **hi** | Hardware Interrupts | Высокий hi — проблема с железом |

**Пример диагностики:**
- LA высокий, us высокий → приложение грузит CPU.
- LA высокий, wa высокий → диск тормозит.
- LA высокий, sy высокий → много системных вызовов.
- LA высокий, id высокий → D-процессы (I/O wait).

---

### 1.5. Память — что смотреть

**free -h** — основная команда:
```bash
free -h
#               total        used        free      shared  buff/cache   available
# Mem:           15Gi       4.2Gi       1.1Gi       234Mi       10Gi       10Gi
# Swap:         2.0Gi          0B       2.0Gi
```

| Колонка | Что означает |
|:---|:---|
| **total** | Всего RAM |
| **used** | Использовано |
| **free** | Полностью свободно |
| **shared** | Разделяемая память (tmpfs) |
| **buff/cache** | Буферы и кэш (можно освободить) |
| **available** | Доступно для приложений (free + buff/cache) |

**Важно:** `free` ≠ `available`. Linux использует свободную память под кэш. Если `free` маленький, но `available` большой — всё в порядке.

**Swap** — если swap используется активно, это признак нехватки RAM.

**Фраза для собеса:**
> `free -h`: смотреть на `available`, а не на `free`. Linux использует свободную память под кэш диска. Высокий swap — признак нехватки RAM.

---

### 1.6. Диски — df и du

**df -h** — сколько места на дисках:
```bash
df -h
# Filesystem      Size  Used Avail Use% Mounted on
# /dev/sda1       100G   45G   55G  45% /
```

**du -sh** — сколько занимает директория:
```bash
du -sh /var/log
du -sh * | sort -hr | head -10   # топ-10 самых больших
```

**Важно:** `df` показывает место, `du` — что его занимает. Если `df` говорит, что диск полон, а `du` не находит больших файлов — возможно, удалённый файл держится процессом (`lsof | grep deleted`).

**Фраза для собеса:**
> `df -h` — место на диске, `du -sh` — что его занимает. Если df полон, а du не находит — удалённый файл держится процессом.

---

### 1.7. inode — что это и зачем

**inode** — структура, хранящая метаданные файла (права, владелец, размер, время). Каждый файл имеет свою inode.

**Проблема:** если закончатся inode, новые файлы не создадутся, даже если место есть.

```bash
df -i
# Filesystem      Inodes  IUsed   IFree IUse% Mounted on
# /dev/sda1      6553600 6553600       0  100% /
```

**Причина:** много маленьких файлов (логи, кэш, сессии).

**Фраза для собеса:**
> inode — метаданные файла. Если закончатся inode, новые файлы не создадутся. Проверять `df -i`. Причина — много маленьких файлов.

---

### 1.8. Дополнительные инструменты

- **iostat** — статистика дисков (tps, kB_read/s, %util).
- **iotop** — топ процессов по дисковому I/O.
- **vmstat** — общая статистика (CPU, память, I/O, swap).
- **sar** — историческая статистика.
- **ss / netstat** — сетевые соединения.
- **iftop / nload** — сетевой трафик.

## Часть 2. Команды с флагами

### 2.1. top / htop

```bash
top                       # интерактивный мониторинг
top -u root               # только процессы root
top -p 1234,5678          # только указанные PID
top -b -n 1               # batch-режим (для скриптов)
htop                      # улучшенная версия
```

**Горячие клавиши в top:**
- `q` — выход
- `k` — убить процесс
- `r` — renice
- `M` — сортировка по памяти
- `P` — сортировка по CPU
- `1` — показать все ядра

---

### 2.2. load average

```bash
uptime                    # LA за 1, 5, 15 минут
cat /proc/loadavg         # LA + количество R/D процессов
nproc                     # количество ядер
```

**Пример:**
```bash
cat /proc/loadavg
# 4.50 2.30 1.20 3/1234 5678
# Первые 3 числа — LA
# 3/1234 — 3 R-процесса из 1234 всего
# 5678 — последний PID
```

---

### 2.3. Память

```bash
free -h                   # человекочитаемый формат
free -m                   # в мегабайтах
free -s 5                 # обновлять каждые 5 секунд
cat /proc/meminfo         # подробная информация
vmstat 1 5                # статистика памяти и swap
```

---

### 2.4. Диски

```bash
df -h                     # место на дисках
df -i                     # inode
du -sh /path              # размер директории
du -sh * | sort -hr | head -10   # топ-10 больших
lsblk                     # структура блочных устройств
fdisk -l                  # разделы дисков
mount                     # смонтированные ФС
cat /etc/fstab            # автоматическое монтирование
```

---

### 2.5. I/O и сеть

```bash
iostat -x 1 5             # статистика дисков
iotop                     # топ по I/O
vmstat 1 5                # общая статистика
ss -tuln                  # сетевые соединения
netstat -tuln             # альтернатива
iftop                     # сетевой трафик
nload                     # нагрузка на сеть
```

---

### 2.6. Дополнительные утилиты

```bash
sar -u 1 5                # историческая статистика CPU
sar -r 1 5                # историческая статистика памяти
pidstat 1 5               # статистика по процессам
dstat                     # комбинированная статистика
```

### Вопрос 5. Что такое "No space left on device", но место на диске есть?

**Ответ:**

**Причина:** закончились **inode**, а не место.

**Как проверить:**
```bash
df -h      # место есть
df -i      # inode = 100%
```

**Как исправить:**
1. Найти директорию с множеством маленьких файлов.
2. Удалить ненужные (логи, кэш, сессии).
3. Настроить ротацию логов.

**Фраза для собеса:**
> "No space left on device", но место есть — закончились inode. Проверить `df -i`. Причина — много маленьких файлов.

### Вопрос 7. Что такое I/O Wait (wa)?

**Ответ:**

**wa (I/O Wait)** — процент времени CPU, когда он ждёт ответа от диска или сети.

**Высокий wa означает:**
- Диск медленный.
- NFS недоступен.
- Проблема с драйвером.

**Как диагностировать:**
```bash
top          # смотреть wa
iostat -x 1 5   # статистика дисков
iotop        # топ по I/O
```

**Фраза для собеса:**
> wa — I/O Wait, CPU ждёт диск. Высокий wa — проблема с диском или NFS. Смотреть iostat, iotop.

---

### Вопрос 8. Что такое swap и когда он используется?

**Ответ:**

**Swap** — область на диске, используемая как расширение RAM. Когда RAM заканчивается, ядро выгружает неиспользуемые страницы в swap.

**Когда используется:**
- RAM заканчивается.
- Процессы неактивны, но занимают память.

**Проблема:** swap на диске медленнее RAM в сотни раз. Активное использование swap = тормоза.

**Как проверить:**
```bash
free -h      # смотреть Swap used
vmstat 1 5   # колонки si, so (swap in/out)
```

**Фраза для собеса:**
> Swap — расширение RAM на диске. Активное использование swap = тормоза. Смотреть `free -h`, `vmstat`.

---

### Вопрос 9. Как найти топ-10 процессов по памяти?

**Ответ:**

```bash
ps aux --sort=-%mem | head -11
```

Или в top:
```bash
top
# Нажать M — сортировка по памяти
```

Или через `ps`:
```bash
ps -eo pid,user,%mem,cmd --sort=-%mem | head -11
```

**Фраза для собеса:**
> `ps aux --sort=-%mem | head -11` или в top нажать `M`.

---

### Вопрос 10. Как найти топ-10 директорий по размеру?

**Ответ:**

```bash
du -sh * | sort -hr | head -10
```

**Разбор:**
- `du -sh *` — размер каждой директории.
- `sort -hr` — сортировка по размеру (человекочитаемо).
- `head -10` — топ-10.

**Если нужно найти по всей системе:**
```bash
du -sh /* 2>/dev/null | sort -hr | head -10
```

**Фраза для собеса:**
> `du -sh * | sort -hr | head -10` — топ-10 директорий по размеру.
