# Подтема 2: Состояния процессов в Linux

---

## Часть 1. Теория

### 1.1. Зачем нужно понимать состояния процессов

Каждый процесс в Linux в любой момент времени находится в **определённом состоянии**. Состояние показывает, что процесс делает прямо сейчас: выполняется, ждёт ввода-вывода, спит или уже завершился.

Понимание состояний нужно для:
- **Диагностики** — почему система тормозит, если CPU свободен (процессы в D).
- **Траблшутинга** — почему процесс не убивается (состояние D или Z).
- **Мониторинга** — что означают буквы в колонке STAT в `ps aux` и `top`.
- **Собеседований** — это топ-1 тема по Linux.

**Где смотреть состояние:**
```bash
ps aux        # колонка STAT
top           # колонка S
htop          # колонка S
cat /proc/<PID>/status | grep State
```

---

### 1.2. Основные состояния процессов

| Код | Название | Описание |
|:---|:---|:---|
| **R** | Running / Runnable | Выполняется на CPU или готов к выполнению (в очереди планировщика) |
| **S** | Sleeping (Interruptible Sleep) | Спит, ждёт события. Может быть прерван сигналом |
| **D** | Uninterruptible Sleep | Ждёт I/O (диск, сеть). **Не реагирует на сигналы** |
| **Z** | Zombie | Мёртв, но запись в таблице процессов осталась |
| **T** | Stopped | Остановлен сигналом SIGSTOP или Ctrl+Z |
| **I** | Idle | Праздный поток ядра (не путать с S) |

---

### 1.3. Разбор каждого состояния

#### R — Running / Runnable

Процесс либо **выполняется на CPU прямо сейчас**, либо **готов к выполнению** и стоит в очереди планировщика.

**Особенности:**
- В многоядерной системе одновременно может быть столько R-процессов, сколько ядер.
- Если R-процессов больше, чем ядер — они ждут в очереди, и `load average` растёт.
- В `ps aux` состояние R встречается редко, потому что снимок делается в момент, когда процесс, скорее всего, спит.

**Пример:**
```bash
ps aux | awk '$8 ~ /^R/'
```

---

#### S — Sleeping (Interruptible Sleep)

Самое **распространённое** состояние. Процесс ждёт события: ввода с клавиатуры, данных из сети, сигнала от другого процесса.

**Особенности:**
- Процесс **может быть прерван сигналом** — например, `kill` разбудит его.
- Если процесс в S — он не занимает CPU.
- В `ps aux` большинство процессов в состоянии S.

**Пример:**
```bash
# Процесс sleep находится в S
sleep 300 &
ps -o pid,stat,cmd -p $!
#   PID STAT CMD
# 12345 S    sleep 300
```

**Дополнительный флаг `s`:** если в STAT стоит `Ss` — процесс является **лидером сессии**.

---

#### D — Uninterruptible Sleep

Самое **опасное** состояние. Процесс ждёт завершения операции ввода-вывода (например, чтения с диска или записи в NFS).

**Особенности:**
- Процесс **НЕ реагирует на сигналы** — даже `kill -9` не сработает.
- Если процесс в D надолго — это признак проблемы с диском, сетью или драйвером.
- D-процессы **учитываются в `load average`**, даже если CPU свободен. Это одна из причин, почему `load average` высокий, а CPU простаивает.
- Убить D-процесс можно только **перезагрузкой** или **устранением проблемы с I/O** (например, отмонтировать зависшую NFS-шару).

**Пример:**
```bash
ps aux | awk '$8 ~ /^D/'
```

**Как диагностировать:**
```bash
# Посмотреть, кто в D
ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'

# wchan показывает, на какой функции ядра процесс застрял
```

**Фраза для собеса:**
> D — uninterruptible sleep. Процесс ждёт I/O и не реагирует на сигналы. Убить нельзя, только перезагрузка или устранение проблемы с диском/сетью. D-процессы учитываются в load average.

---

#### Z — Zombie

Процесс **завершился**, но родитель **не вызвал `wait()`** и не забрал exit-код.

**Особенности:**
- Зомби **не занимает CPU и память**.
- Занимает **слот в таблице процессов** (PID).
- **Нельзя убить через `kill -9`** — он уже мёртв.
- Если зомби накопится много — закончатся PID.

**Как появляется:**
```
1. Дочерний процесс завершается
2. Ядро отправляет родителю SIGCHLD
3. Родитель должен вызвать wait() или waitpid()
4. Если не вызывает — ребёнок остаётся зомби
```

**Как избавиться:**
1. **Заставить родителя вызвать `wait()`** — перезапустить родителя.
2. **Убить родителя** — тогда зомби станет приёмным для systemd (PID 1), и systemd вызовет `wait()`.
3. **Перезагрузить систему** — крайний случай.

**Пример:**
```bash
ps aux | grep defunct
# user  1234  0.0  0.0  0  0 ?  Z  10:00  0:00 [myapp] <defunct>
```
`<defunct>` — признак зомби.

**Фраза для собеса:**
> Зомби — завершившийся процесс, чей родитель не вызвал wait(). Не занимает ресурсы, но занимает PID. Убить через kill -9 нельзя — нужно убить родителя или перезапустить его.

---

#### T — Stopped

Процесс **остановлен** сигналом SIGSTOP или Ctrl+Z.

**Особенности:**
- Процесс не выполняется, но остаётся в памяти.
- Можно **продолжить** сигналом SIGCONT (`kill -CONT <PID>` или `fg`).
- Используется для отладки (gdb) и управления заданиями.

**Пример:**
```bash
sleep 300 &
# Ctrl+Z
[1]+  Stopped   sleep 300
ps -o pid,stat,cmd -p $!
#   PID STAT CMD
# 12345 T    sleep 300
```

**Как продолжить:**
```bash
fg %1          # вернуть на передний план
bg %1          # продолжить в фоне
kill -CONT 12345
```

---

#### I — Idle

**Праздный поток ядра**. Не путать с S (sleeping). I — это потоки ядра, которые не выполняют работу и не ждут события. Встречается редко, в основном в `htop`.

---

### 1.4. Дополнительные флаги в STAT

В `ps aux` колонка STAT может содержать **несколько символов**. Первый — состояние, остальные — дополнительные флаги.

| Флаг | Значение |
|:---|:---|
| `<` | Высокий приоритет |
| `N` | Низкий приоритет (nice) |
| `L` | Страницы заблокированы в памяти |
| `s` | Лидер сессии |
| `l` | Многопоточный |
| `+` | Foreground-процесс |
| `D` | Uninterruptible sleep |

**Пример:**
```
Ss    — спящий лидер сессии
Ssl   — спящий лидер сессии, многопоточный
S+    — спящий foreground-процесс
R<    — выполняется с высоким приоритетом
```

---

### 1.5. Связь состояний с load average

**Load average** — это среднее количество процессов в состоянии **R** и **D** за 1, 5 и 15 минут.

**Формула:** `LA = R + D`

- Если LA = числу ядер — система загружена оптимально.
- Если LA > числа ядер — процессы ждут CPU.
- Если LA высокий, а CPU простаивает — виноваты D-процессы (I/O wait).

**Пример:**
```bash
uptime
# 10:00:00 up 1 day, load average: 4.50, 2.30, 1.20
```
На 4-ядерной системе LA = 4.50 — небольшая перегрузка.

**Как понять причину:**
```bash
top
# Смотрите на us, sy, wa
# Если wa высокий — виноваты D-процессы (I/O)
```

## Часть 2. Команды с флагами

### 2.1. Просмотр состояний

```bash
ps aux                          # колонка STAT
ps -eo pid,stat,cmd             # только PID, STAT и команда
ps -eo pid,stat,wchan,cmd       # с функцией ядра (для D-процессов)
top                             # колонка S
htop                            # колонка S
cat /proc/<PID>/status          # строка State
```

**Фильтрация по состоянию:**
```bash
ps aux | awk '$8 ~ /^R/'        # только R
ps aux | awk '$8 ~ /^S/'        # только S
ps aux | awk '$8 ~ /^D/'        # только D
ps aux | awk '$8 ~ /^Z/'        # только Z
ps aux | awk '$8 ~ /^T/'        # только T
ps aux | grep defunct           # зомби (но покажет сам grep!)
```

---

### 2.2. Диагностика D-процессов

```bash
# Показать D-процессы с функцией ядра
ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'

# Показать, какие процессы в D
top -b -n 1 | awk '$8 ~ /^D/'

# Посмотреть I/O статистику
iostat -x 1 5
iotop
```

**wchan** — показывает, на какой функции ядра процесс застрял. Например, `nfs_wait` — ждёт NFS, `blkdev_issue_flush` — ждёт диск.

---

### 2.3. Работа с зомби

```bash
# Найти зомби (правильно)
ps aux | awk '$8 ~ /^Z/'
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /^Z/'

# Исключить сам grep
ps aux | grep defunct | grep -v grep
ps aux | grep "[d]efunct"

# Найти родителя зомби
ps -o pid,ppid,stat,cmd -p <PID_зомби>

# Убить родителя (если это безопасно)
kill <PPID>
```

---

### 2.4. Управление остановленными процессами

```bash
Ctrl+Z                  # приостановить текущий процесс
jobs                    # посмотреть задания
fg %1                   # продолжить на переднем плане
bg %1                   # продолжить в фоне
kill -CONT <PID>        # продолжить процесс
kill -STOP <PID>        # остановить процесс
```

---

### 2.5. Мониторинг load average

```bash
uptime                  # LA за 1, 5, 15 минут
top                     # LA + us, sy, wa, id
cat /proc/loadavg       # LA + количество R/D процессов
```

**Пример:**
```bash
cat /proc/loadavg
# 4.50 2.30 1.20 3/1234 5678
# Первые 3 числа — LA
# 3/1234 — 3 R-процесса из 1234 всего
# 5678 — последний PID
```

### Вопрос 1. Какие состояния процессов существуют в Linux?

**Ответ:**

В Linux у процесса есть **5 основных состояний** (плюс одно редкое):

| Код | Название | Что означает |
|:---|:---|:---|
| **R** | Running / Runnable | Выполняется на CPU или готов к выполнению |
| **S** | Sleeping (Interruptible) | Спит, ждёт события. Можно прервать сигналом |
| **D** | Uninterruptible Sleep | Ждёт I/O. Не реагирует на сигналы |
| **Z** | Zombie | Завершился, но родитель не вызвал wait() |
| **T** | Stopped | Остановлен (SIGSTOP, Ctrl+Z) |
| **I** | Idle | Праздный поток ядра |

**Где смотреть:**
```bash
ps aux        # колонка STAT
top           # колонка S
cat /proc/<PID>/status | grep State
```

**Фраза для собеса:**
> Основные состояния: R (running), S (interruptible sleep), D (uninterruptible sleep), Z (zombie), T (stopped). Плюс I (idle) для потоков ядра.

---

### Вопрос 2. Что такое состояние D и чем оно опасно?

**Ответ:**

**D (Uninterruptible Sleep)** — процесс ждёт завершения операции ввода-вывода (диск, сеть, NFS). В этом состоянии процесс **не реагирует на сигналы** — даже `kill -9` не сработает.

**Почему опасно:**
1. **Нельзя убить** — только перезагрузка или устранение проблемы с I/O.
2. **Учитывается в load average** — если D-процессов много, LA растёт, хотя CPU простаивает.
3. **Признак проблемы** — застрявший диск, недоступная NFS-шара, сбойный драйвер.

**Как диагностировать:**
```bash
ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'
```
Колонка `wchan` показывает, на какой функции ядра процесс застрял (например, `nfs_wait` — ждёт NFS).

**Как исправить:**
- Проверить диск: `iostat -x 1 5`, `dmesg | tail`.
- Проверить NFS: `mount | grep nfs`, `df -h`.
- В крайнем случае — перезагрузка.

**Фраза для собеса:**
> D — uninterruptible sleep. Процесс ждёт I/O и не реагирует на сигналы. Убить нельзя, только перезагрузка. D-процессы учитываются в load average.

---

### Вопрос 3. Что такое зомби-процесс и как его убить?

**Ответ:**

**Зомби (Z)** — процесс, который **завершился**, но родитель **не вызвал `wait()`** и не забрал exit-код. Запись о процессе остаётся в таблице процессов.

**Почему нельзя убить через `kill -9`:**
Зомби — **уже мёртвый** процесс. Сигналы отправляются только живым процессам. У зомби нет кода, который мог бы обработать сигнал.

**Как избавиться:**
1. **Заставить родителя вызвать wait()** — перезапустить родительский процесс.
2. **Убить родителя** — тогда зомби станет приёмным для systemd (PID 1), и systemd вызовет `wait()`.
3. **Перезагрузить систему** — крайний случай.

**Пример:**
```bash
ps aux | awk '$8 ~ /^Z/'
# user  1234  0.0  0.0  0  0 ?  Z  10:00  0:00 [myapp] <defunct>

# Найти родителя
ps -o pid,ppid,stat,cmd -p 1234

# Убить родителя
kill <PPID>
```

**Почему это важно:**
Зомби не занимают CPU и память, но занимают **PID**. Если их накопится много — закончатся PID для новых процессов. В контейнерах это критично: если PID 1 не обрабатывает SIGCHLD, зомби накапливаются.

**Фраза для собеса:**
> Зомби — завершившийся процесс, чей родитель не вызвал wait(). Убить через kill -9 нельзя — нужно убить родителя или перезапустить его.

---

### Вопрос 4. Что означает состояние S и чем оно отличается от D?

**Ответ:**

**S (Interruptible Sleep)** — процесс спит, ждёт события (ввода, сигнала, данных из сети). **Может быть прерван сигналом** — `kill` разбудит его.

**D (Uninterruptible Sleep)** — процесс ждёт I/O. **Не может быть прерван сигналом** — `kill -9` не сработает.

**Разница:**

| Характеристика | S | D |
|:---|:---|:---|
| Прерывание сигналом | Да | Нет |
| Причина | Ожидание события | Ожидание I/O |
| Влияние на LA | Нет | Да |
| Опасность | Нет | Высокая |

**Пример:**
```bash
# S — обычный sleep
sleep 300 &
ps -o pid,stat,cmd -p $!
# 12345 S sleep 300

# D — ждёт диск (пример)
ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'
```

**Фраза для собеса:**
> S — interruptible sleep, можно прервать сигналом. D — uninterruptible sleep, нельзя прервать, ждёт I/O, учитывается в load average.

**Как читать:**

**Пример:**

### Вопрос 9. Как найти процессы в состоянии D и что делать?

**Ответ:**

**Как найти:**
```bash
# Способ 1
ps aux | awk '$8 ~ /^D/'

# Способ 2 — с функцией ядра
ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'

# Способ 3
top -b -n 1 | awk '$8 ~ /^D/'
```

**Что делать:**
1. **Посмотреть `wchan`** — на какой функции ядра процесс застрял.
   ```bash
   ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'
   ```
2. **Проверить I/O** — `iostat -x 1 5`, `iotop`.
3. **Проверить dmesg** — `dmesg | tail` (ошибки диска).
4. **Проверить NFS** — `mount | grep nfs`, `df -h`.
5. **Если диск сбойный** — заменить диск, перезагрузиться.
6. **Если NFS завис** — отмонтировать (`umount -f`).

**Фраза для собеса:**
> Найти D-процессы: `ps -eo pid,stat,wchan,cmd | awk '$2 ~ /^D/'`. Смотреть wchan — на какой функции застрял. Проверить iostat, dmesg, NFS. Убить нельзя — только перезагрузка или устранение проблемы.

### Вопрос 10. Почему процесс может быть в состоянии D и не убиваться?

**Ответ:**

**Причина:** процесс ждёт завершения **операции ввода-вывода** на уровне ядра. Ядро не может прервать эту операцию, потому что она критична для целостности данных.

**Примеры:**
- **Диск** — процесс ждёт чтения/записи. Если диск сбойный — процесс застревает.
- **NFS** — процесс ждёт ответа от NFS-сервера. Если сервер недоступен — процесс в D.
- **Драйвер** — сбойный драйвер может заставить процесс застрять в D.

**Почему `kill -9` не работает:**
Сигналы обрабатываются **после** возврата из системного вызова. Пока процесс в D — он не может обработать сигнал. Ядро доставит сигнал только когда процесс выйдет из D.

**Что делать:**
1. **Устранить причину** — починить диск, восстановить NFS.
2. **Перезагрузить систему** — если причина неустранима.
3. **В крайнем случае** — `echo 1 > /proc/sys/kernel/sysrq` + `Alt+SysRq+B` (перезагрузка).

**Фраза для собеса:**
> D-процесс ждёт I/O на уровне ядра. Сигналы обрабатываются после возврата из системного вызова, поэтому kill -9 не работает. Нужно устранить причину (диск, NFS) или перезагрузиться.

## Часть 4. Важное замечание про поиск зомби

Когда вы делаете `ps aux | grep defunct`, в выводе **всегда** появляется сам `grep`, потому что его командная строка содержит слово `defunct`. Это **ложный зомби** — на самом деле у него STAT = `S+`, а не `Z`.

**Правильные способы поиска зомби:**
```bash
ps aux | awk '$8 ~ /^Z/'                   # фильтр по STAT
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /^Z/' # альтернатива
ps aux | grep "[d]efunct"                  # трюк с квадратными скобками
ps aux | grep defunct | grep -v grep       # исключить сам grep
```

**Фраза для собеса:**
> Когда делаешь `ps aux | grep X`, всегда появляется сам grep. Чтобы исключить его — `grep -v grep` или `[X]`-трюк. А лучше фильтровать по колонке STAT: `awk '$8 ~ /^Z/'`.
