# Подтема 3: Сигналы в Linux

---

## Часть 1. Теория

### 1.1. Что такое сигнал

**Сигнал** — это программное прерывание, которое ядро отправляет процессу, чтобы сообщить о каком-то событии. Сигнал — это способ **асинхронного взаимодействия** между процессами или между ядром и процессом.

**Как это работает:**
1. Кто-то (ядро, другой процесс, пользователь) отправляет сигнал процессу.
2. Ядро доставляет сигнал процессу.
3. Процесс либо **обрабатывает** сигнал (если есть обработчик), либо **игнорирует** его (если так настроено), либо **завершается** (по умолчанию).

**Важно:** сигнал — это не команда, а уведомление. Процесс сам решает, что делать с сигналом.

---

### 1.2. Зачем нужны сигналы

- **Управление процессами** — остановить, продолжить, завершить.
- **Уведомления** — сообщить процессу, что что-то произошло (например, изменился конфиг).
- **Обработка ошибок** — сообщить о делении на ноль, ошибке сегментации.
- **Завершение работы** — попросить процесс корректно завершиться.

---

### 1.3. Основные сигналы

В Linux **64 сигнала**. Вот самые важные:

| Сигнал | Номер | Действие по умолчанию | Что делает |
|:---|:---|:---|:---|
| **SIGTERM** | 15 | Завершить | Нормальное завершение (по умолчанию в kill) |
| **SIGKILL** | 9 | Завершить | Принудительное убийство, нельзя перехватить |
| **SIGHUP** | 1 | Завершить | Hangup — перезапуск или перечитать конфиг |
| **SIGINT** | 2 | Завершить | Прерывание (Ctrl+C) |
| **SIGQUIT** | 3 | Завершить + core dump | Выход с дампом памяти (Ctrl+\) |
| **SIGSTOP** | 19 | Остановить | Приостановка, нельзя перехватить |
| **SIGTSTP** | 20 | Остановить | Приостановка (Ctrl+Z) |
| **SIGCONT** | 18 | Продолжить | Продолжить выполнение |
| **SIGUSR1** | 10 | Завершить | Пользовательский сигнал 1 |
| **SIGUSR2** | 12 | Завершить | Пользовательский сигнал 2 |
| **SIGCHLD** | 17 | Игнорировать | Ребёнок завершился (родителю) |
| **SIGPIPE** | 13 | Завершить | Запись в закрытый pipe |
| **SIGALRM** | 14 | Завершить | Таймер истёк |

---

### 1.4. Три категории сигналов

**1. Завершающие (Terminate)**
- SIGTERM (15) — можно перехватить.
- SIGKILL (9) — нельзя перехватить.
- SIGINT (2) — Ctrl+C.
- SIGQUIT (3) — Ctrl+\.

**2. Останавливающие (Stop)**
- SIGSTOP (19) — нельзя перехватить.
- SIGTSTP (20) — Ctrl+Z.

**3. Продолжающие (Continue)**
- SIGCONT (18) — продолжить после остановки.

---

### 1.5. SIGTERM vs SIGKILL

Это **самый частый вопрос** на собеседовании.

| Характеристика | SIGTERM (15) | SIGKILL (9) |
|:---|:---|:---|
| Перехват | Да | Нет |
| Обработка | Процесс может сохранить данные | Нет |
| Завершение | Graceful | Мгновенное |
| Использование | По умолчанию | Крайний случай |
| Можно игнорировать | Да | Нет |

**Правило:** сначала всегда SIGTERM, дайте процессу шанс завершиться корректно. SIGKILL — только если процесс завис.

**Фраза для собеса:**
> SIGTERM — можно перехватить, graceful shutdown. SIGKILL — нельзя перехватить, мгновенное убийство. Сначала всегда SIGTERM, SIGKILL — крайний случай.

---

### 1.6. SIGHUP — перечитать конфиг

**SIGHUP (1)** изначально означал "hangup" — разрыв соединения с терминалом. Когда вы закрывали терминал, все процессы сессии получали SIGHUP и завершались.

**Сейчас используется демонами как команда перечитать конфигурацию** без перезапуска.

**Примеры:**
- `nginx -s reload` — отправляет SIGHUP.
- `kill -HUP <PID>` — перечитать конфиг.

**Важно:** если процесс не обрабатывает SIGHUP, он просто завершится.

---

### 1.7. Ctrl+C, Ctrl+Z, Ctrl+\ — какие сигналы

| Комбинация | Сигнал | Номер | Что делает |
|:---|:---|:---|:---|
| Ctrl+C | SIGINT | 2 | Прерывание |
| Ctrl+Z | SIGTSTP | 20 | Приостановка |
| Ctrl+\ | SIGQUIT | 3 | Выход с core dump |
| Ctrl+D | — | — | Не сигнал! EOF (конец ввода) |

**Важно:** Ctrl+D — это **не сигнал**, а конец ввода (EOF).

---

### 1.8. Обработка сигналов в программах

Программа может:
1. **Обработать сигнал** — зарегистрировать обработчик (handler).
2. **Игнорировать сигнал** — `signal(SIGTERM, SIG_IGN)`.
3. **Оставить по умолчанию** — ядро выполнит действие по умолчанию.

**Пример на Python:**
```python
import signal
def handler(signum, frame):
    print("Получен SIGTERM, сохраняю данные...")
    # сохранить данные
    exit(0)
signal.signal(signal.SIGTERM, handler)
```

**Почему это важно для DevOps:**
В Kubernetes при удалении пода отправляется SIGTERM, затем даётся `terminationGracePeriodSeconds` (30 секунд), и только потом SIGKILL. Если приложение не обрабатывает SIGTERM — данные теряются.

---

### 1.9. SIGCHLD — сигнал родителю

**SIGCHLD (17)** — сигнал, который ядро отправляет **родителю**, когда его дочерний процесс завершается или останавливается.

**Зачем нужен:**
1. Родитель узнаёт, что ребёнок завершился.
2. Родитель должен вызвать `wait()` или `waitpid()`, чтобы забрать exit-код.
3. Если родитель не вызовет `wait()` — ребёнок станет **зомби**.

**Почему это важно:**
В контейнерах PID 1 должен обрабатывать SIGCHLD, иначе зомби накопятся. Поэтому используют `tini` или `dumb-init`.

## Часть 2. Команды с флагами

### 2.1. kill — отправить сигнал по PID

```bash
kill 1234                 # SIGTERM (15) по умолчанию
kill -9 1234              # SIGKILL
kill -HUP 1234            # SIGHUP (перечитать конфиг)
kill -INT 1234            # SIGINT
kill -STOP 1234           # SIGSTOP (остановить)
kill -CONT 1234           # SIGCONT (продолжить)
kill -l                   # список всех сигналов
kill -l 9                 # расшифровка номера 9
```

---

### 2.2. pkill — убить процесс по имени

```bash
pkill nginx               # SIGTERM всем процессам nginx
pkill -9 nginx            # SIGKILL
pkill -HUP nginx          # SIGHUP (перечитать конфиг)
pkill -u user1            # все процессы пользователя
pkill -f "python script"  # по полной командной строке
```

---

### 2.3. killall — убить все процессы с именем

```bash
killall nginx             # SIGTERM всем nginx
killall -9 nginx          # SIGKILL
killall -HUP nginx        # SIGHUP
```

**Разница между pkill и killall:**
- `pkill` — по шаблону имени (regex).
- `killall` — по точному имени.

---

### 2.4. Работа с заданиями (jobs)

```bash
sleep 300 &               # запустить в фоне
jobs                      # посмотреть задания
fg %1                     # вернуть на передний план
bg %1                     # продолжить в фоне
Ctrl+Z                    # приостановить (SIGTSTP)
kill %1                   # SIGTERM заданию №1
kill -9 %1                # SIGKILL заданию №1
```

---

### 2.5. nohup и setsid — защита от SIGHUP

```bash
nohup command &           # игнорировать SIGHUP, вывод в nohup.out
nohup command > out.log 2>&1 &   # свой лог
setsid command            # новая сессия (защита от SIGHUP)
disown %1                 # убрать задание из списка jobs
```

**Зачем:** когда вы закрываете терминал, все процессы сессии получают SIGHUP. `nohup` и `setsid` защищают от этого.

---

### 2.6. trap — обработка сигналов в bash

```bash
trap 'echo "Получен SIGINT"; exit' INT
trap 'echo "Получен SIGTERM"; cleanup' TERM
trap '' INT               # игнорировать SIGINT
trap - INT                # сбросить обработчик
```

**Пример скрипта:**
```bash
#!/bin/bash
cleanup() {
    echo "Убираю за собой..."
    rm -f /tmp/tempfile
    exit 0
}
trap cleanup SIGTERM SIGINT
while true; do
    sleep 1
done
```

### Вопрос 1. Что такое сигнал в Linux?

**Ответ:**

**Сигнал** — это программное прерывание, которое ядро отправляет процессу для уведомления о событии. Сигналы — это способ асинхронного взаимодействия между процессами или между ядром и процессом.

**Как работает:**
1. Кто-то отправляет сигнал (ядро, процесс, пользователь через kill).
2. Ядро доставляет сигнал процессу.
3. Процесс либо обрабатывает (если есть handler), либо игнорирует, либо завершается (по умолчанию).

**Всего в Linux 64 сигнала.** У каждого есть номер и имя (например, SIGTERM = 15).

**Фраза для собеса:**
> Сигнал — программное прерывание для уведомления процесса о событии. Всего 64 сигнала. Процесс может обработать, игнорировать или оставить по умолчанию.

### Вопрос 2. Чем отличается SIGTERM от SIGKILL?

**Ответ:**

**SIGTERM (15)** — запрос на нормальное завершение. Процесс может его перехватить, сохранить данные, закрыть соединения и завершиться корректно.

**SIGKILL (9)** — принудительное убийство. Нельзя перехватить, заблокировать или проигнорировать. Ядро немедленно завершает процесс.

**Разница:**

| Характеристика | SIGTERM (15) | SIGKILL (9) |
|:---|:---|:---|
| Перехват | Да | Нет |
| Обработка | Graceful | Мгновенное |
| Использование | По умолчанию | Крайний случай |

**Правило:** сначала SIGTERM, дать процессу шанс. SIGKILL — только если завис.

**Фраза для собеса:**
> SIGTERM — можно перехватить, graceful shutdown. SIGKILL — нельзя перехватить, мгновенное убийство. Сначала всегда SIGTERM, SIGKILL — крайний случай.

### Вопрос 3. Какие сигналы отправляются при Ctrl+C, Ctrl+Z, Ctrl+\?

**Ответ:**

| Комбинация | Сигнал | Номер | Что делает |
|:---|:---|:---|:---|
| Ctrl+C | SIGINT | 2 | Прерывание (interrupt) |
| Ctrl+Z | SIGTSTP | 20 | Приостановка (terminal stop) |
| Ctrl+\ | SIGQUIT | 3 | Выход с core dump |

**Важно:**
- **Ctrl+D — не сигнал!** Это EOF (конец ввода).
- SIGINT можно перехватить (например, nano не закрывается при Ctrl+C).
- SIGTSTP можно перехватить, но обычно процесс останавливается.
- SIGQUIT создаёт core dump — полезно для отладки.

**Фраза для собеса:**
> Ctrl+C — SIGINT (2), Ctrl+Z — SIGTSTP (20), Ctrl+\ — SIGQUIT (3). Ctrl+D — не сигнал, это EOF.

### Вопрос 4. Что такое SIGHUP и где он используется?

**Ответ:**

**SIGHUP (1)** — изначально означал "hangup" — разрыв соединения с терминалом. Когда вы закрывали терминал, все процессы сессии получали SIGHUP и завершались.

**Сейчас используется:**
1. **Перечитать конфиг** — демоны (nginx, sshd, postgres) обрабатывают SIGHUP и перечитывают конфигурацию без перезапуска.
2. **Завершение при закрытии терминала** — если процесс не обрабатывает SIGHUP, он завершится.

**Примеры:**
```bash

```

**Защита от SIGHUP:**
```bash
nohup command &           # игнорировать SIGHUP
setsid command            # новая сессия
disown %1                 # убрать из jobs
```

**Фраза для собеса:**
> SIGHUP — hangup. Используется для перечитывания конфига без перезапуска. При закрытии терминала все процессы сессии получают SIGHUP. Защита — nohup, setsid.

### Вопрос 7. Что такое SIGCHLD и зачем он нужен?

**Ответ:**

**SIGCHLD (17)** — сигнал, который ядро отправляет **родителю**, когда его дочерний процесс завершается или останавливается.

**Зачем нужен:**
1. Родитель узнаёт, что ребёнок завершился.
2. Родитель должен вызвать `wait()` или `waitpid()`, чтобы забрать exit-код.
3. Если родитель не вызовет `wait()` — ребёнок станет **зомби**.

**По умолчанию SIGCHLD игнорируется**, но это не значит, что зомби не будет.

**Пример обработки в Python:**
```python
import signal
def handler(signum, frame):
    pid, status = os.wait()
    print(f"Ребёнок {pid} завершился с кодом {status}")
signal.signal(signal.SIGCHLD, handler)
```

**Почему это важно:**
В контейнерах PID 1 должен обрабатывать SIGCHLD, иначе зомби накопятся. Поэтому используют `tini` или `dumb-init`.

**Фраза для собеса:**
> SIGCHLD отправляется родителю при завершении ребёнка. Родитель должен вызвать wait(), иначе ребёнок станет зомби. В контейнерах PID 1 должен обрабатывать SIGCHLD.

### Вопрос 8. Что такое trap в bash и зачем он нужен?

**Ответ:**

**trap** — встроенная команда bash для **обработки сигналов** в скриптах.

**Синтаксис:**
```bash
trap 'команды' СИГНАЛ
```

**Примеры:**
```bash
trap 'echo "Получен SIGINT"; exit' INT
trap 'cleanup' SIGTERM SIGINT
trap '' INT               # игнорировать
trap - INT                # сбросить
```

**Зачем нужен:**
1. **Cleanup** — удалить временные файлы при завершении.
2. **Graceful shutdown** — сохранить данные, закрыть соединения.
3. **Логирование** — записать, что скрипт был прерван.

**Пример:**
```bash
#!/bin/bash
cleanup() {
    echo "Убираю за собой..."
    rm -f /tmp/tempfile
    exit 0
}
trap cleanup SIGTERM SIGINT
while true; do
    sleep 1
done
```

**Фраза для собеса:**
> trap — обработка сигналов в bash. Используется для cleanup, graceful shutdown, логирования. Пример: trap cleanup SIGTERM.

**Ответ:**

**Проблема:** при закрытии терминала все процессы сессии получают SIGHUP и завершаются.

   ```bash
   tmux new -s mysession
   ```

**Фраза для собеса:**
> nohup игнорирует SIGHUP, setsid создаёт новую сессию, disown убирает из jobs. Для сервисов — systemd. Для интерактивной работы — screen/tmux.

### Вопрос 10. Что происходит при kill -9 с процессом в состоянии D?

**Ответ:**

**Ничего.** Процесс в состоянии **D (Uninterruptible Sleep)** не реагирует на сигналы — даже SIGKILL.

**Почему:**
Сигналы обрабатываются **после возврата из системного вызова**. Пока процесс в D — он ждёт завершения I/O на уровне ядра. Ядро доставит сигнал только когда процесс выйдет из D.

**Что делать:**
1. **Устранить причину** — починить диск, восстановить NFS.
2. **Перезагрузить систему** — если причина неустранима.
3. **В крайнем случае** — `Alt+SysRq+B` (жёсткая перезагрузка).

**Почему это важно:**
D-процессы учитываются в load average. Если их много — LA растёт, хотя CPU простаивает. Это признак проблемы с I/O.

**Фраза для собеса:**
> D-процесс не реагирует на сигналы, включая kill -9. Сигналы обрабатываются после возврата из системного вызова. Нужно устранить причину (диск, NFS) или перезагрузиться.
